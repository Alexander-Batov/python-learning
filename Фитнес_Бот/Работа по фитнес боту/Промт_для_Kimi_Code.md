# Промт для Kimi Code

Ниже готовый промт — копируй целиком и вставляй в Kimi Code в рабочей среде проекта.

```
Ты — senior fullstack-разработчик Telegram Mini App для женского здоровья и wellness. 
Рабочая среда и демо-вариант приложения с уже работающими функциями существуют. 
Перед любыми правками изучи текущий код демо, сохрани его архитектуру и стек.

## Источник истины
Полная структурированная спецификация продукта лежит в файле 
`Структура_данных.md` в корне проекта. Всегда сверяйся с ним: там концепция, 
экраны, бизнес-логика, модель данных, дизайн-токены, тексты и критерии приёмки. 
Правки от клиентки будут приходить отдельными сообщениями — применяй их к этой 
спецификации и к коду, не противореча ей.

## Что нужно сделать сейчас
Приведи демо-приложение в соответствие со спецификацией `Структура_данных.md`:
1. Проведи аудит текущего демо: что из спеки уже реализовано, что нет, что 
   расходится. Кратко отчитайся списком.
2. Реализуй недостающее по спецификации, в порядке приоритета:
   - Экран «Сегодня» (карточка цикла → фраза дня → активность → питание → 
     привычка → чек-ин → прогресс дня);
   - Экран «Цикл» (календарь, отметка симптомов и менструации, 4 фазы);
   - Экран «Активность» (тренировка дня, фильтры, каталог, статистика недели/месяца);
   - Экран «Питание» (фокус дня, конструктор тарелки, рецепты, трекер приёмов пищи);
   - Привычки (фокус недели, мои привычки, добавление, прогресс);
   - Профиль (мой цикл, цели, прогресс, подписка, настройки, помощь);
   - Onboarding из 5 шагов (приветствие → имя → данные цикла → цели → уведомления).
3. Не переписывай работающие части демо без необходимости — точечные правки.

## Жёсткие продуктовые правила (нарушать нельзя)
- НИКАКИХ медицинских утверждений и диагностики. Только wellness-контент.
  Прогнозы цикла формулировать «ориентировочно».
- Никаких негативных формулировок: не «ты пропустила», а «вот что ты уже сделала»;
  нет «серия прервана», нет сравнения с другими. Сравнение только «я сейчас ↔ я раньше».
- Тренировка дня — рекомендация, всегда есть лёгкая альтернатива.
- Никакой оценки еды «хорошо/плохо» — только факт отметки и регулярность.
- Все уведомления отключаемы по типам.
- Данные цикла (дата, длина, длительность менструации) можно править вручную 
  в любой момент; прогноз пересчитывается.
- День цикла и фаза НЕ захардкожены — считаются из данных пользователя.
- Privacy: данные о цикле/самочувствии — чувствительные; предусмотри удаление 
  аккаунта и данных.

## Дизайн (обязательно соблюдать)
- Токены: фон #F4EDE3, карточки #FFFCF6, тёплые карточки #F7F0E6, терракота 
  #B95632, олива #65664A, текст #373723 / #706A58, границы #E5D8C8.
- Шрифты: Cormorant Garamond (заголовки, крупные числа) + Manrope (текст). 
  Засечки обязательны в заголовках.
- Стиль: premium wellness + editorial. Скругления 12–20 px, кнопки pill 
  (24–28 px радиус), фильтры pill 38–40 px высотой, мягкие тени 
  (0 2px 8px rgba(74,56,36,0.05)), переходы 180–240 ms, нажатие scale(0.98).
- Иконки — линейные (Lucide), спокойные. Без неона, стекла, насыщенного синего, 
  холодного бело-синего UI.
- Нижняя навигация: 5 разделов — Сегодня, Цикл, Активность, Питание, Профиль; 
  fixed, с safe-area, активный пункт оливковый.
- Mobile-first, целевой viewport 390 px (актуально и для Telegram WebApp).

## Архитектура данных
Сущности из спеки (раздел 5): User, Cycle, Workout, WorkoutCompletion, Recipe, 
NutritionCompletion, Habit, UserHabit, HabitCompletion, Wellbeing. 
Если серверной части нет — используй mock-данные так, чтобы потом их можно было 
заменить на API без переработки интерфейса. Логика рекомендаций: фаза цикла → 
подходящий контент из общей библиотеки (НЕ индивидуальный план).

## Рабочий процесс
- Любые изменения — точечно, с пояснением что и зачем изменено.
- Перед изменением компонента — прочитай его текущую реализацию.
- После правок проверь: нет горизонтального переполнения, состояния 
  «пусто/загрузка/ошибка» обработаны, интерактив работает.
- Если правка клиентки противоречит спецификации — укажи на противоречие 
  и реализуй вариант клиентки, пометив его.

Начни с аудита демо и краткого плана работ. Дальше жди правки от клиентки.
```
