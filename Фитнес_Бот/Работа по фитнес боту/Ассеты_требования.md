# Ассеты: требования и порядок подгрузки

Статус сейчас: в приложении свёрстаны все экраны, используются временные изображения
(скриншоты/плейсхолдеры). Когда клиентка пришлёт финальные материалы — заменяем
через манифест, **не трогая вёрстку**.

---

## 1. Что запросить у клиентки (можно отправить как есть)

**Фотографии (минимум для старта):**
- [ ] Hero-фото главной карточки тренировки (девушка в терракотовой форме) — горизонтальное, ≥1600 px по ширине, свободная левая часть под текст
- [ ] Фото для карточек тренировок (йога, растяжка, кардио, силовая) — 4–8 шт., квадрат или 4:3, ≥800 px
- [ ] Фото для карточек фаз цикла (4 шт., женщина в спокойных позах)
- [ ] Фото рецептов/питания (завтрак, обед, ужин, перекус, тарелка для «Правила тарелки») — ≥800 px
- [ ] Фото для «Вечернего восстановления» (чай, свеча, дневник)
- [ ] Аватар пользователя (можно любое тёплое фото, ≥400 px)
- [ ] Иллюстрации рук для «Правила ладошка—кулак» (4 шт.) — либо пришлёт, либо дорисуем

**Видео тренировок (когда будет готово):**
- [ ] По 1 видео на тренировку из библиотеки (стартово 3–5 шт.)
- Формат: MP4 (H.264), вертикальное 9:16 или квадрат 1:1, 720p достаточно
- Длительность: финальное видео или фрагменты по 15–60 сек на упражнение
- Вес: до ~20 МБ на файл (для Telegram Mini App критично)
- Постер-картинка к каждому видео (кадр из видео, JPG ≥800 px)

**Бренд:**
- [ ] Логотип/иконка (SVG или PNG ≥512 px)
- [ ] Ботаническая веточка в векторе (SVG) — если есть исходник; иначе оставляем нашу SVG-иллюстрацию

**Форматы:** JPG/WebP для фото (WebP приоритетно), SVG для иллюстраций. Скриншоты и картинки из мессенджеров **не подходят** — качество будет заметно хуже.

## 2. Как собрать то, что уже есть, в лучшем качестве

1. Попросить исходники у дизайнера/нейросети, где генерировались экраны (Midjourney/ChatGPT — выгрузка в полном разрешении).
2. Временный апскейл скринов: любой ИИ-апскейлер (Topaz Gigapixel, Upscayl — бесплатно) поднимет 853×1280 до 1700×2560 для черновой версии; цвета потом выровнять в одной цветокоррекции.
3. Фото вырезать из скринов как крайний вариант (низкое качество, только для внутреннего теста).

## 3. Порядок подгрузки в код (для Kimi Code / Claude Code)

1. **Сейчас (уже должно быть сделано или делаем первым):** все изображения подключаются
   не по имени файла в компонентах, а через `assets/manifest.ts` (или JSON) — маппинг
   `ключ → файл`. Вёрстка знает только ключи (`hero-workout`, `phase-luteal` и т.д.).
2. Финальные файлы кладутся в `assets/images/` и `assets/videos/` с теми же ключами.
3. Видео: `<video preload="none" poster="{постер}">`, ленивая загрузка, запуск по тапу
   (автовоспроизведение в Telegram WebApp лучше не использовать).
4. Оптимизация при подгрузке: фото → WebP (качество 80–85), ширина ≤1600 px;
   проверить вес страницы.
5. После замены — прогнать визуальную сверку экранов с референсами ещё раз
   (цветокоррекция новых фото может «уехать» от палитры).

## 4. Чек-лист приёмки ассетов

- [ ] Все ключи из манифеста закрыты файлами (нет 404/broken image)
- [ ] Единая тёплая цветокоррекция (терракотовый свет, без холодных сине-серых фото)
- [ ] Видео открывается и играет внутри Telegram (iOS + Android), есть постер
- [ ] Вес каждого экрана с медиа — разумный (фото < 300 КБ, видео < 20 МБ)
- [ ] Скриншот-сверка экранов после замены
