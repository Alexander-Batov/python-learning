# AGENTS.md

Файл для ИИ-агентов, работающих с этим репозиторием. Читатель ничего не знает о проекте — всё описано с нуля и только по фактическому содержимому.

## Обзор проекта

`E:\Projects` — это личная учебная рабочая папка (Python), а не единое приложение. Внутри несколько независимых мини-проектов без общей системы сборки:

| Каталог/файл | Что это |
|---|---|
| `Katya_Bot/` | **Главный проект** — Telegram-бот на aiogram 3 для сбора контактов клиентов, отправки прайса и квиза. Единственный с конфигурацией и деплоем. |
| `YandexCode/` | Два учебных скрипта с решениями задач в стиле Яндекс.Тренировок (ввод/вывод через stdin). |
| `2_Семак/Лаба_1_Батов.ipynb` | Университетская лабораторная (25 ячеек): интегралы через sympy, интегральные суммы через numpy. |
| `first_project.py` | Первый учебный скрипт — расчёт среднего значения и прогноз дохода. |
| `Homework.py` | Однострочное домашнее задание (арифметическое выражение). |
| `venv/` | Виртуальное окружение Python 3.12.6 (см. «Окружение»). |
| `.idea/` | Настройки PyCharm. |

Ключевых файлов конфигурации уровня проекта (`pyproject.toml`, `setup.py`, `package.json` и т.п.) **нет**. Единственный манифест — `Katya_Bot/requirements.txt` и `Katya_Bot/amvera.yml` (конфигурация деплоя).

## Технологический стек

- **Python 3.12.6** (венв `venv/`), бот таргетирует Python 3.11 в облаке Amvera.
- **aiogram 3.x** (в венве стоит 3.31.0, в requirements указано `aiogram>=3.4`) — асинхронный Telegram-бот, long polling, FSM (`aiogram.fsm`).
- **python-dotenv** — загрузка секретов из `.env`.
- **SQLite** (модуль `sqlite3` из стандартной библиотеки) — хранение клиентов.
- **matplotlib** (+ numpy как его зависимость) — построение радарной диаграммы результатов квиза (`chart.py`).
- **sympy, numpy** — только в Jupyter-лабораторной.
- IDE — PyCharm (папка `.idea/`).

## Структура и архитектура Katya_Bot

Запускаемый файл — `bot.py` (`python bot.py`); он импортирует `config`, `db` и `chart`.

- `config.py` — вся настройка через переменные окружения (`.env` в корне `Katya_Bot/`):
  - `BOT_TOKEN` — токен бота;
  - `ADMIN_IDS` — список Telegram ID админов через запятую (whitelist для `/export`);
  - `CHANNEL_ID` — числовой ID канала (`-100...`) или `@имя_канала`;
  - `CHANNEL_URL` — ссылка на канал для кнопки подписки;
  - `MATERIALS_PATH` — захардкожен как `materials/price.pdf`.
- `db.py` — тонкая обёртка над SQLite, файл БД — `clients.db` (путь можно переопределить через `DB_PATH`). Таблица `clients`: `id, tg_id, username, name, phone, order_info, created_at`. Функции: `init()`, `add_client(...)`, `all_clients()`.
- `chart.py` — построение радарной диаграммы итогов квиза: `build_radar_chart(scores)` принимает 5 баллов блоков (0–3), рисует через matplotlib (`Agg`-бэкенд) и возвращает PNG в `io.BytesIO`, на диск не пишет.
- `bot.py` — вся логика в одном файле (~250 строк):
  - reply-клавиатуры `menu`, `contact_kb`, `yes_no_kb` и inline-клавиатура подписки;
  - FSM `Form` (phone → order) — сценарий «Оставить контакт»: кнопка «Поделиться контактом» → имя и телефон → свободный текст заказа → запись в БД;
  - проверка подписки на канал (`is_subscribed` / `require_sub`) — обязательная перед контактом и прайсом; если `CHANNEL_ID` не задан, проверка отключена;
  - отправка прайса (`materials/price.pdf`) по кнопке или `/materials`;
  - квиз «5 пазлов эксперта»: 15 утверждений «Да/Нет» (списки `QUIZ_QUESTIONS`, `QUIZ_RESULTS` в коде), подсчёт баллов по 5 блокам по 3 вопроса (Готовность, Экспертность, Аудитория, Продукт, Реализация), результат — персональная радарная диаграмма блоков (`chart.py`, matplotlib, PNG в `io.BytesIO`) с текстом по порогам (≤6, ≤9, ≤12, ≤15) в подписи;
  - `/export` (только для `ADMIN_IDS`) — выгрузка всех клиентов в `clients_export.csv` в кодировке `utf-8-sig` с разделителем `;` (чтобы Excel корректно открывал кириллицу).

Данные и ассеты лежат рядом с кодом: `clients.db`, `clients_export.csv`, `materials/`. Бот работает через **long polling** — веб-хук и веб-сервер не используются.

## Команды

```bash
# установка зависимостей (из Katya_Bot/)
pip install -r requirements.txt

# запуск бота (из Katya_Bot/, нужен заполненный .env)
python bot.py

# учебные скрипты запускаются напрямую
python first_project.py
python "YandexCode/Словарь Синонимов.py"   # читает stdin
```

Тестов, линтеров и CI **нет ни в одном из проектов**. Проверка изменений — ручной запуск скрипта/бота.

## Деплой

Деплоится только `Katya_Bot` — в облако **Amvera** (русский PaaS) по манифесту `Katya_Bot/amvera.yml`: окружение python, toolchain pip 3.11, установка из `requirements.txt`, запуск `bot.py`, персистентный диск смонтирован в `/data` (порт 80 указан, но бот ходит через polling, порт фактически не нужен). Перед деплоем секреты задаются как переменные окружения в панели Amvera — файл `.env` туда не загружается.

## Стиль кода

- Все комментарии, строки интерфейса бота и имена сущностей — **на русском**; AGENTS.md тоже пишется на русском.
- `bot.py`, `config.py`, `db.py` — обычный аккуратный Python в духе PEP 8: snake_case, аннотации типов у ключевых функций, `logging` вместо print, обработка ошибок через try/except.
- В учебных скриптах (`YandexCode/`, `first_project.py`, лабораторная) стиль свободный: встречаются транслитерированные идентификаторы (`Sinonim`, `slova`, `Unic_Lines`), CamelCase, отладочные `print`. При изменении учебных файлов сохраняйте их авторский стиль, не «чините» его.
- Зависимости подключаются напрямую (`import config`, `import db`, `import chart`), бот и его модули должны запускаться с рабочей директорией `Katya_Bot/` (пути к `materials/` и БД относительные).

## Безопасность

- `Katya_Bot/.env` содержит реальный токен бота и ID админов — **не коммитить и не выводить в логи**. В репозитории нет корневого `.gitignore`: при добавлении `Katya_Bot/` в git сначала создайте `.gitignore` (как минимум `.env`, `__pycache__/`, `clients.db`, `*.pyc`).
- Доступ к админ-командам `/export` ограничен проверкой `message.from_user.id in config.ADMIN_IDS` — при добавлении новых админских команд сохраняйте эту проверку.
- Телефоны клиентов хранятся в открытом виде в SQLite и в CSV-выгрузке — не публикуйте эти файлы.

## Подводные камни

- Windows + Git Bash: в командах Python используйте Windows-пути (`E:/Projects/...`), а не `/e/Projects/...`; пути с кириллицей в Git Bash могут отображаться с битой кодировкой, но файлы открываются нормально.
- `materials/price.pdf` обязан лежать рядом с `bot.py` — бот обращается к нему по относительному пути. Результаты квиза рисуются на лету и на диск не пишутся; папка `quiz_results/` со статичными картинками боту больше не нужна (файлы пока оставлены).
- Если измените схему таблицы `clients`, помните: `db.init()` делает только `CREATE TABLE IF NOT EXISTS`, миграций нет — существующая `clients.db` не обновится сама.
